The rustup book

引言

_rustup_installs Rust Programming Language 使您能够轻松地在稳定、贝塔和夜间编译器之间切换并随时更新。 它使交叉编译更加简单，使用普通平台标准库的二进制构建。它运行在所有平台上。Rust 支持。

查看 [Concepts](concepts/index.md章，以了解生死是如何工作的，以及它使用的一些术语。 [Installation](installation/index.md章涉及安装程序和启动程序。

Rustup 及其使用手册的源代码可以在以下地址找到：https://github.com/rust-lang/rustup。如果您发现任何问题，请访问问题跟踪系统。

Rustup的发布说明可以在CHANGELOG中找到。

安装

请按照 https://www.rust-lang.org/tools/install 中的说明进行操作。如果那样做仍然无法解决问题，还有[其他安装方法]可供选择。

rustup负责将rustc、cargo以及rustup等其他标准工具安装到 Cargo 的bin目录下。在 Unix 系统中，该目录位于$HOME/.cargo/bin；在 Windows 系统中则位于%USERPROFILE%\.cargo\bin。正是这个目录，也是cargo install用于安装 Rust 程序和 Cargo 插件的目标目录。

这个目录将存在于你的 $PATH 环境变量中，这意味着你可以无需额外配置就从 shell 中运行它们。打开一个新的 shell，然后输入以下内容：

rustc --version

如果你看到类似 rustc 1.19.0 (0ade33941 2017-07-17) 这样的内容，那么你就已经准备好开始使用 Rust 了。如果你觉得 Rust 不适合你，可以通过运行 rustup self uninstall 来完全从你的系统中移除它。

选择安装位置

rustup允许你通过设置CARGO_HOME和RUSTUP_HOME这两个环境变量来自定义你的安装过程。在运行rustup-init脚本之前，就可以进行这些设置。如环境变量配置部分所述，RUSTUP_HOME变量用于指定rustup程序的根目录，该目录用于存储安装好的工具链和配置选项。CARGO_HOME变量则包含由cargo使用的缓存文件。

请注意，在使用工具链时，必须确保这些环境变量始终被设置，并且 CARGO_HOME/bin 位于 $PATH 环境变量中。

安装最新版本

如果在安装rustup时指定了夜间更新的频道，那么rustup-init脚本会默认进行“强制安装”。所谓“强制安装”意味着会安装该夜间更新的频道，而不会考虑是否缺少你需要的组件。如果你希望安装带有夜间更新频道的rustup，并且确保它包含了你需要的组件，那么你需要分两步来完成这个过程。例如，如果你想进行全新安装的话

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --default-toolchain none -y

接下来，你可以安装 nightly，从而让 rustup 降级，直到找到你需要的组件。

rustup toolchain install nightly --allow-downgrade --profile minimal --component clippy

这在持续集成过程中可以发挥重要作用，能够快速为您提供符合您要求的工具链。

启用 Bash、Fish、Zsh 或 PowerShell 的Tab键补全功能

rustup 现在支持为 Bash、Fish、Zsh 和 PowerShell 生成补全脚本。有关详细信息，请参阅 rustup help completions，其原理很简单，只需使用以下其中一种方式即可。

# Bash
$ rustup completions bash > ~/.local/share/bash-completion/completions/rustup

# Bash (macOS/Homebrew)
$ rustup completions bash > $(brew --prefix)/etc/bash_completion.d/rustup.bash-completion

# Fish
$ mkdir -p ~/.config/fish/completions
$ rustup completions fish > ~/.config/fish/completions/rustup.fish

# Zsh
$ rustup completions zsh > ~/.zfunc/_rustup

# PowerShell v5.0+
$ rustup completions powershell >> $PROFILE.CurrentUserCurrentHost
# or
$ rustup completions powershell | Out-String | Invoke-Expression

注意：可能需要重新启动你的终端窗口，以便这些更改生效。

对于 zsh，您需要在 ~/.zshrc 中添加以下行，然后才能使用 compinit：

fpath+=~/.zfunc

在 Xonsh 中，你可以通过安装xontrib-fish-completer来重新使用 Fish 补全功能。

Windows系统

rustup 在Windows上和Unix上相同，但是对于Windows上的Rust 开发者有一些特殊的考虑。 正如在Rust下载页面上提到的, Windows上有两种 ABIs：Visual Studio使用的原生(MSVC) ABI， 和 GNU ABI 使用 [海湾合作委员会工具链] (https://gcc.gnu.org/)。 你需要哪种版本的Rust在很大程度上取决于你想要与哪些C/C++ 库相互作用: 因为与Visual Studio生产的软件互换使用MSVC building of Rus; 对于使用 [MinGW/MSYS2 工具链] (https://www.msys2.org/建立的 GNU 软件的互联，请使用 GNU 构建。

当针对MSVC ABI时，Rust 还需要一个安装Visual Studio，因此rustc 可以使用它的链接和库。

Windows GNU 构建不需要额外的软件进行基本使用。 然而，许多库箱将无法编译，直到安装完满的 MSYS2。

在 Windows 上默认rustup 配置Rust来瞄准MSVC ABI 时，它是一个 i686-pc-windows-msvc 的目标管, x86_64-pc-windows-msvc, 或 aarch64-pc-windows-msvc 取决于主机 Windows OS 的 CPU 结构。 rustup 选择安装的工具链，除非通过 toolchain 规格 将被编译在目标管主页上运行，并默认以此为目标主机。

您可以使用 “rusup 设置默认主机” 或在安装过程中更改此行为。

例如，要明确选择32位 MSVC 主机：

$ rustup set default-host i686-pc-windows-msvc

或者选择64 位 GNU 工具链：

$ rustup set default-host x86_64-pc-windows-gnu

由于MSVC ABI提供了与其他Windows软件的最佳交互功能，建议它用于大多数目的。 GNU 工具链总是可用的，即使您默认不使用它。只需安装`rusup toolchain 安装’：

$ rustup toolchain install stable-gnu

您不需要切换工具链来支持所有窗口目标；单个工具链支持所有四个x86窗口目标：

$ rustup target add x86_64-pc-windows-msvc
$ rustup target add x86_64-pc-windows-gnu
$ rustup target add i686-pc-windows-msvc
$ rustup target add i686-pc-windows-gnu

用同一编译器指定不同目标的更多详细信息，请参阅 Cross-compilation。

MSVC 前置条件

若要将程序编译为exe 文件，Rust 需要链接、库和 Windows API 导入库。 对于msvc目标，这些可以通过 Visual Studio 获得。

自动安装

如果您尚未安装 Visual Studio，那么 rustup-init 将自动安装先决条件。 这意味着您可以跳过此页面的其余部分。 然而，它安装了可能不适合所有用户的 Visual Studio 社区版本。 它对个人、学术界和开放源码的使用是免费的，但对其他用途，如专利企业软件则是免费的。 用户应该询问他们组织哪个版本对他们是正确的。详情请参阅许可证条款。

WinGet

Alternatively Visual Studio can be installed via the WinGet package manager, which should be avaliable by default on recent versions of Windows. Run the following command in powershell or the command prompt:

winget install --id Microsoft.VisualStudio.2022.Community --source winget --force --override "--add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.VC.Tools.ARM64 --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --addProductLang En-us"

如果你已经拥有 Visual Studio 的许可证，可以在上述命令中将“Community”替换为“BuildTools”。

缺少Windows SDK

If after running the above command the Windows 11 SDK is missing then you may need to manually install it, which can also be done via WinGet. First search for the avaliable versions:

winget search --source winget --id Microsoft.WindowsSDK.

其他安装方法

主要的安装方法，如 https://rustup.rs 中所述，因平台不同而有所差异：

  • 在Windows系统中，根据您的操作系统架构，下载并运行为x86_64-pc-windows-msvc或aarch64-pc-windows-msvc目标版本构建的 rustup-init.exe 程序。通常，这种构建版本是应该在Windows上安装的 rustup。这需要使用MSVC prerequisites。如果您希望默认安装GNU工具链或i686工具链，可以在安装时通过 --default-host 标志进行交互式修改，或者在安装后通过 rustup set default-host 进行修改。
  • 在Unix系统中，在您的shell中运行 curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh。这会下载并运行rustup-init.sh，而后者又会下载并运行适合您平台的 rustup-init 可执行文件的正确版本。

rustup-init支持传递参数，这些参数可以通过 shell 脚本来传递。以下是一些示例：

$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --help
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --no-modify-path
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --default-toolchain nightly
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --default-toolchain none
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- --profile minimal --default-toolchain nightly

使用包管理器

请注意，rustup项目并不维护本部分中提到的任何包。如果您在通过包管理器安装 rustup 时遇到任何问题，请联系该包的维护者以获取更多信息。

通用提示

不同的包管理器在管理 rustup 时采取的方法略有不同。使用你喜欢的包管理器安装 rustup 之后，通常有两种可能性：

  • 如果你的包管理器已经提供了 rustup 命令，同时还提供了对 Rust 工具的代理选项，比如 rustc 和 cargo，那么通常只需要选择一个默认的工具链（例如 stable）即可。

    $ rustup default stable

    截至 2024 年 12 月 23 日，以下软件的情况也是如此：APT、homebrew以及pacman。

  • 如果你的包管理器只提供了rustup-init命令，那么只需运行该命令即可。

    $ rustup-init

    这将使你能够完成rustup的初始设置，配置由rustup管理的所有代理服务器，并安装默认的工具链。

    截至 2024 年 12 月 23 日，DNF就是这种情况。

安装完成后，请确保 rustup 代理程序（通常位于 $HOME/.cargo/bin 目录下）能够通过 $PATH 环境变量被正确访问。这样一来，你就可以正常运行 rustup、rustc、cargo 等命令了。

APT

从 Debian 13（trixie）和 Ubuntu 24.04（noble）版本开始，你可以使用apt来安装rustup：

$ sudo apt install rustup

Homebrew

你可以使用 brew 来安装 rustup[^不是rust]：

$ brew install rustup

请注意，在这个rustup发行版中，像rustc和cargo这样的 Rust 工具默认并不通过$PATH路径可用（更多细节请参考homebrew-core#177582）。您可能需要将$(brew --prefix rustup)/bin添加到$PATH中，以便更容易访问这些工具。

已经安装了Rust吗？

其他包管理器也提供了Rust版本，您可能希望使用这些打包的工具链，例如用于分发包的开发。您也可以选择使用由 rustup 管理的工具链，比如nightly或beta版本。通常情况下， rustup 会提示您已经安装了Rust，并拒绝进行安装。不过，您可以通过 rustup 来安装Rust，使其与您已使用的打包Rust工具链共存。

使用现有的Rust工具链来安装rustup

当你首次使用 rustup 安装 Rust 时，需要传递 -y 选项，使其忽略已打包的 Rust 工具链，并安装一个由 rustup 管理的工具链，将其安装到 ~/.cargo/bin 中。将那个目录添加到你的 $PATH 中（或者让 rustup 帮你完成，无需传递 --no-modify-path）。然后，为了告诉 rustup 你的系统工具链的位置，请运行：

rustup toolchain link system /usr

你可以将“system”当作一个工具链来使用，就像使用“nightly”一样。例如，使用工具链快捷方式，你可以运行 cargo +system build 来使用系统工具链进行构建，或者运行 cargo +nightly build 来使用 nightly 版本进行构建。

如果您想要开发系统工具链(例如发行软件包)，您可能想要将其变成您的默认工具链：

rustup default system

确保正确的 $PATH 配置

有时候，上述步骤可能无法正常工作，在运行本应被 rustup 代理的命令时，你可能会看到奇怪的错误信息。例如，在运行 cargo +stable --version 时，你可能会遇到以下错误：

error: no such command: `+stable`

        Cargo does not handle `+toolchain` directives.
        Did you mean to invoke `cargo` through `rustup` instead?

这意味着 cargo 目前并不是一个 rustup 的代理，而你的 $PATH 需要被修复。

事实上，在任何安装了rustup的机器上，您都希望**rustup代理在$PATH**中首先显示，并覆盖任何其他Rust安装。别担心：如上所述，这些阴影安装可以通过使用“rustup toolchain link”命令的rustup来采用。

首先需要采取的确切步骤来制作rusup proxies 可能会根据您的系统环境而变化。 但通常是为了更改您的 shell 配置文件(s) 中某些行的评估顺序。

使之更加清晰， 让我们看看一个Mac 的例子，这个Mac 同时从 rustup.rs 和自制安装的 “rust” 中获取了正常的生成。 正确的方式 在这个环境中配置 .profile 的方式是：

eval $(/opt/homebrew/bin/brew shellenv)
. $HOME/.cargo/env

在这个示例中，这两行代码都位于 $PATH 之前，因此最后那一行会优先执行，使得 rustup 代理能够覆盖 homebrew 安装的 rust。另一方面，如果将这些代码的位置颠倒，就会引发上述错误。

如果不确定，你可以通过打印当前 $PATH 的 status，并使用 echo $PATH | xargs -n1 来调试你的 shell 配置，同时注意 $CARGO_HOME/bin 的排序（默认是 $HOME/.cargo/bin）与你的包管理器中的 bin 目录的排序是否一致。

在修复之后， cargo +stable --version 的输出结果应该与以下其中一种情况类似，具体取决于您是否安装了 stable 工具链。

  • cargo 1.85.1 (d73d2caf9 2024-12-31)

  • error: toolchain 'stable' is not installed

概念

Rustup 的工作原理

rustup是一个用于管理多个 Rust 工具链的多路器。它负责安装和管理这些工具链，并通过一组安装在了~/.cargo/bin下的工具来统一调用这些工具链。rustc和cargo这两个可执行文件被安装到了~/.cargo/bin目录下，它们实际上都是用来代理调用真实工具链的代理程序。rustup还提供了机制，可以通过重新配置这些代理程序来轻松切换当前使用的工具链。

因此，当 rustup 首次安装后，运行 rustc 将会调用位于 $HOME/.cargo/bin/rustc 目录下的编译器。而一旦你之后通过 rustup default nightly 将默认使用的编译器设置为 nightly 版本，那么同样的代理程序就会用来运行 nightly 版本的编译器了。

这类似于 Ruby 的rbenv、Python 的pyenv，或者 Node 的nvm。

术语表

  • 频道——Rust 有三个不同的发布渠道：稳定版、测试版和最新版本。更多详细信息请参考频道设置章节

  • 工具链——所谓“工具链”，指的是完整的 Rust 编译器（rustc）及相关工具（如cargo）的安装环境。工具链的规格说明中通常会包含相关的发布渠道、版本信息，以及该工具链运行所需的平台。

  • 目标平台——rustc能够生成适用于多种平台的代码。这里的“目标平台”指的是代码将被生成的平台。默认情况下，cargo和rustc会使用主机上的工具链平台作为目标平台。如果想要为不同的目标平台构建代码，通常需要先通过rustup target命令安装该目标平台的标准库。更多细节请参考交叉编译章节。

  • 组件——每个版本的 Rust 都包含多个“组件”，其中一些是必需的（如rustc），而另一些则是可选的（如clippy）。更多详细信息请参考组件部分。

  • 配置文件——为了便于管理组件，会定义一种“配置文件”来分组组件。更多细节请参考配置文件章节。

  • 代理——是一种针对常见 Rust 组件（如rustc）的封装层，旨在将 CLI 接口调用转发到活跃的 Rust 工具链中。更多细节请参考代理机制章节。

频道

Rust 被释放到三种不同的“通道”：稳定、贝塔和夜晚。稳定释放每6周（偶尔发布点数）。 测试版发布是将出现在下一次稳定版本中。夜间发布是每晚发布一次。 请参阅Rust Book关于Rust的火车发布模型的更多详细信息。发布计划已张贴到Rust Forge。 rustup 有助于安装不同的频道，随时更新，并且易于在它们之间切换。

在安装了发布通道之后，可以使用 rustup 将已安装的版本更新到该通道上最新的版本。更多详细信息，请参见 保持 Rust 的更新部分。

rustup 也可以安装特定版本的 Rust, 例如1.45.2 或 夜间-2020-07-27。 请参阅 [Toolchains](toolchains.md章，以了解安装不同频道和发布版本的更多信息。 请参阅 [Overrides](../overrides.md章，以了解工具链之间切换和将您的项目置于特定的工具链中的详细信息。

每晚使用 Rust

rustup 可以让您轻松地访问每夜编译器及其实验功能。要添加它，只需要运行 `rustup toolchain 夜间安装’：

$ rustup toolchain install nightly
info: syncing channel updates for 'nightly'
info: downloading toolchain manifest
info: downloading component 'rustc'
info: downloading component 'rust-std'
info: downloading component 'rust-docs'
info: downloading component 'cargo'
info: installing component 'rustc'
info: installing component 'rust-std'
info: installing component 'rust-docs'
info: installing component 'cargo'

  nightly installed: rustc 1.9.0-nightly (02310fd31 2016-03-19)

现在必须每晚安装一次，但没有激活。要测试它，您可以从每晚的工具链中运行一个命令。

$ rustup run nightly rustc --version
rustc 1.9.0-nightly (02310fd31 2016-03-19)

但你想要在一段时间内使用它的可能性更大。要切换到全局夜晚，请使用 rusup default 夜晚 来更改 默认 ：

$ rustup default nightly
info: using existing install for 'nightly'
info: default toolchain set to 'nightly'

  nightly unchanged: rustc 1.9.0-nightly (02310fd31 2016-03-19)

现在你运行cargo或rustc时，你将运行夜间编译器。

每运行一次rustup update后，夜间版软件也会随之更新。除了稳定版之外，夜间版软件也会得到更新。

$ rustup update
info: syncing channel updates for 'stable'
info: syncing channel updates for 'nightly'
info: checking for self-update
info: downloading self-update

   stable unchanged: rustc 1.7.0 (a5d1e7a59 2016-02-29)
  nightly unchanged: rustc 1.9.0-nightly (02310fd31 2016-03-19)

每晚可用

每晚工具链可能无法构建，因此对于任何给定的日期和目标平台，可能没有可用的工具链。 此外，夜间构建可能会发布缺少非默认的 components (例如clippy)。 因此，很难找到正常工作的夜晚。 使用 rustup-components-history 项目来查找最近夜间工具链和组件的构建状态。

当你尝试安装或更新 夜间 通道时，rustup 将检查是否缺少所需或以前安装过的组件。 如果缺失，rustup 将自动搜索包含所需组件的旧版本。有几种方法可以改变这种行为：

  • 使用 “–force” 标志来rusup toolchain install 来强制它安装最新版本，即使缺少一个组件。
  • 使用 “–profile” 标志来使用 “rusup toolchain install” 来使用一个不包含缺失组件的不同配置文件。 例如，--profile=minimal 应该始终能够运行，因为最小的集是需要存在的。更多详细信息请参阅 Profiles。
  • 安装包含您需要的组件的特定日期。例如，“rusup toolchain new 2020-07-27”。 然后您可以使用 overrides 引脚到指定的版本。

工具链

许多rustup命令处理的 toolchains，Rust编译器的单一安装。rustup 支持多种类型的工具链。 官方发布的最基本的音轨 channels: stable, beta 和 nightly; 但rustup 也可以从官方档案中为备用主机平台和本地建筑安装工具链。

工具链规范

标准发行频道工具链名称有以下表单：

<channel>[-<date>][-<host>]

<channel>       = stable|beta|nightly|<versioned>[-<prerelease>]
<versioned>     = <major.minor>|<major.minor.patch>
<prerelease>    = beta[.<number>]
<date>          = YYYY-MM-DD
<host>          = <target-triple>

“通道”是一个命名的发布频道，一个主要和次要的版本号，如1.42，或一个完全指定的版本号，如1.42.0。 频道名称可选择附加归档日期，比如“2014-12-18晚”， 在这种情况下，将从该日期的归档中下载工具链。

最后，主机可以指定为目标管。 这对于在 64 位平台上安装 32 位编译器或在 Windows 上安装 基于 MSVC 的工具链最有用。例如：

$ rustup toolchain install stable-x86_64-pc-windows-msvc

为方便起见，将推断被遗漏的目标管道的要素，因此可以写上：

$ rustup toolchain install stable-msvc

没有给频道命名的工具链名称可以用来命名自定义工具链。

自定义工具链接

为了方便从事 Rust 开发的开发者，rustup 可以负责管理 Rust 工具链的本地构建工作。如果你想向 rustup 说明你的构建过程，可以运行以下命令：

$ rustup toolchain link my-toolchain path/to/my/toolchain/sysroot

例如，在 Ubuntu 系统中，你可以将 rust-lang/rust 克隆到 ~/rust 中，然后构建它，最后运行：

$ rustup toolchain link my-toolchain ~/rust/build/x86_64-unknown-linux-gnu/stage2/
$ rustup default my-toolchain

现在，你可以将 my-toolchain 命名为任何其他 rustup 工具链。为你的每个 rust-lang/rust 工作区创建一个 rustup 工具链，并可以使用 rustup run my-toolchain rustc 轻松测试它们。

因为 rust-lang/rust 这个工具树并不包含 Cargo，当为自定义工具链调用 cargo 且无法使用时， rustup 会尝试从某个发布渠道使用 cargo，优先选择 ‘nightly’，然后是 ‘beta’ 或 ‘stable’。

组件

每个 toolchain 有几个“组件”，其中一些是必需的(例如rustc)，还有一些是可选的(例如clippy)。 rusup component 命令用于管理已安装的组件。 例如，运行 rusup 组件列表 以查看可用和已安装组件的列表。

在安装 “–component” 标志的工具链时可以添加组件。例如：

rustup toolchain install nightly --component rust-docs

组件可以添加到已安装的 “rusup 组件” 命令的工具链中：

rustup component add rust-docs

为了更容易选择哪些组件被安装，rustup具有“配置文件“的概念，提供不同组件的命名组合。 更多细节请参阅 Profiles。

大多数组件有目标三重后缀，例如rustc-x86_64-apple-darwin，表示组件所要使用的平台。

现有组件的组别可能因不同的版本和工具链而不同。

  • rustc — Rust编译器和 Rustdoc。 
  • cargo — Cargo 是一个软件包管理器和构建工具。
  • rustfmt — Rustfmt 是自动格式化代码的工具。
  • rust-std — 这是Rust 标准库。 rustc支持的每个目标都有一个单独的rust-std组件，如rust-std-x86_64-pc-winds-msvc。 更多细节请参阅 Cross-compilation。
  • rust-docs - 这是[Rust文档]的本地副本(https://doc.rust-lang.org/)。 使用 “rusup doc” 命令在 web 浏览器中打开文档。运行 “rusup doc –help” 获取更多选项。
  • rust-analyzer — rust-analyzer 是一个语言服务器，为编辑器和 IDE 提供支持。
  • clippy - Clippy 是一个直线工具，为常见错误和风格选择提供额外的检查。
  • miri - Miri 是一个实验性的Rust 解释器，可以用于检查未定义的行为。
  • rust-src — 这是Rust标准库源代码的本地副本。 这可以通过一些工具来使用，例如 rust-analyzer，为标准库中的功能提供自动完成； Miri 是Rust解释器； 和 Cargo 的实验 build-std功能，允许您在本地重建标准库。
  • rust-mingw — — 它包含一个链接库和平台库，用于在 x86_64-pc-winds-gnu 平台上建造。
  • llvm-tools — 此组件包含了一个 LLVM工具集。 **这个组件尚未稳定下来，可能会在将来改变，并且是按原样提供。 * 单独的LVM工具的可用性可能会随着LLVM版本而改变(包括移除具体的LLVM工具)。 不受编译器或工具链稳定性保证的约束。 请参阅#85658。
  • rustc-dev — — 这个组件包含编译器作为库。 大多数用户将不需要这样做； 它仅用于连接到编译器的开发_of_工具，如修改 Clippy。

组件可用性

并非所有组件都适用于所有的工具链。 特别是在夜间频道上，如果某些组件处于故障状态，它们可能不会被包含。 所有组件的当前状态可以在 rusup 组件历史 页面找到。 详情请查看每晚可用性部分。

配置文件

rustup 的概念是“profiles”。 他们属于 components组，您可以在安装新的Rust 工具链时选择下载。 此时可用的配置文件是 minimal 、 default 和 complete：

  • 最小化 配置文件包含尽可能少的组件来获取一个工作编译器(rustc, rust-std, 和 cargo)。 如果您不使用本地文档，建议在Windows系统上使用此组件(大量文件可能会导致某些抗病毒系统的问题)， and in CI。
  • 默认 配置文件包含所有组件在 最小 配置文件中，并添加 rust-docs 、 rustfmt 和 clippy 。 默认情况下，这个配置文件将被 rustup 使用，它是推荐给一般使用的配置文件。
  • 完整 配置文件包括所有通过“rustup”提供的组件。 永远不应使用，因为它包含了包含在元数据中的 every 组件，因此几乎总是失败。 如果您正在寻找安装诸如miri 或 IDE 集成工具(rust-analyzer)的方法， 您应该使用 “默认” 配置文件并手动安装所需的附加组件。 通过使用 “rusup component add” 或使用 “-c” 安装工具链。

要更改默认使用的配置文件 rusup install ，您可以使用 rusup set profile 命令。 例如，要选择您可以使用的最小配置文件：

rustup set profile minimal

您也可以直接选择安装工具链时使用的配置文件：

rustup install --profile <name>

第一次安装 rustup 时，也可以选择默认配置文件 通过选择 “定制安装” 选项交互，或通过通过 “–profile=” 标志编程。 配置文件只会影响新安装的工具链：通常可以稍后安装个别组件： rusup 组件添加 。

代理服务器

rustup 为通用的Rust工具提供了一些包装器。 这些被称为_proxies_ 并代表由各种 components提供的命令。

代理服务器列表目前在 rustup 中静态，如下所示：

  • rustc是Rustc编程语言的编译器，由项目本身提供，来自rustc组件’。

  • rustdoc是一个在 rustc 组件中分配的工具，它帮助您生成Rust项目的文档。

  • cargo是Rust 包管理器，它下载你的包依赖，编译你的包，提供可分发的包，并将它们上传到箱子。 o (Rust Community的软件包注册表)。它来自于“cargo”组件。

  • rust-lldb、rust-gdbb、rust-gdbgui分别是lldb、gdb和gdbgui的包裹。 封装程序可以让一些预印Rust值，并通过其脚本接口为调试器添加一些便利功能。

  • rust-analyzer 是Rust IDE 集成工具的一部分。 它执行语言服务器协议以允许IDEs和编辑，例如Visual Studio代码。 Vim, 或 Emacs, 访问你正在编辑的Rust 代码的语义。 它来自rust-analyzer组件’。

  • cargo-clipppy和clippy-driver都与clippy工具相关，它为常见错误和风格选择提供额外的检查，它来自clippy组件’。

  • cargo-miri 是Rust中级代表制的实验性解释器，它来自miri 部分。

  • rls 是一个废弃的 IDE 工具，它已被rt-analyzer所替代。它来自rls组件。

基本使用

保持 Rust 的更新状态

Rust 分布在三个不同的不同的发行频道：稳定、贝塔和夜间。 rustup 默认使用稳定通道，代表最新版本的 Rustup。稳定每六周发布一次新版本。

当发行新版本Rust时，只需输入rustup update以更新：

$ rustup update
info: syncing channel updates for 'stable'
info: downloading component 'rustc'
info: downloading component 'rust-std'
info: downloading component 'rust-docs'
info: downloading component 'cargo'
info: installing component 'rustc'
info: installing component 'rust-std'
info: installing component 'rust-docs'
info: installing component 'cargo'
info: checking for self-update
info: downloading self-update

  stable updated: rustc 1.7.0 (a5d1e7a59 2016-02-29)

保持rustup更新

If your rustup was built with the no-self-update feature, it can not update itself. This is not the default, and only versions of rustup built with --no-default-features, or obtained from a third-party distributor who has disabled it (such as NixOS).

否则Rusup可以更新自己。可以使用 “自动自更新” 配置变量来控制Rustup自动更新机制。 此设置支持三个值：enable 和 disabl 和 chec-only check 。

  • disable 将确保不会自动进行自我更新操作。
  • enable表示rustup update和类似命令也会检查并安装到Rustup上的任何更新。
  • “只勾选“会导致任何自动更新来检查和报告任何更新，但不会自动安装它们。

无论自动更新 是否为enable ，你都可以通过运行 rustup 自我更新 来请求Rustup更新自己到最新版本的 rustup 。 这将不会下载新的工具链：

$ rustup self update
info: checking for self-update
info: downloading self-update

在每次调用的基础上禁用自我更新

在运行 rustup update 或 rustup toolchain install 时，也可以通过 --no-self-update 传递参数来抑制自身的更新。

帮助系统

rustup命令行有一个内置的帮助系统，提供更多关于每个命令的信息。运行 rustup help 以获取概述。 每个子命令的详细帮助也是可用的。例如，运行 “rusup toolchain install –help” 以获取安装 toolchains。 

覆盖

rustup在执行像rustc这样的已安装命令时，会自动确定使用哪个[工具链]。有几种方法可以控制和覆盖所使用的工具链：

  1. 在命令行上使用的工具链覆盖短语，例如“cargo + beta“。
  2. 环境变量 RUSTUP_TOOLCHAIN。
  3. 一个目录覆盖，使用 rusup override 命令设置。
  4. [rust-toolchain.toml] 文件。
  5. 默认的工具链。

工具链的选择按照上述顺序进行，首先选择第一个被指定的工具链。不过有一个例外：目录覆盖和rust-toolchain.toml文件由于更接近当前目录，因此也被优先选择。也就是说，这两种覆盖方法是通过遍历目录树来发现的，而距离当前目录更近的rust-toolchain.toml文件会被优先选择，而不是距离更远的目录覆盖方式。

为了验证哪个工具链是活跃的，你可以使用 rustup show。

工具链覆盖的简写方式

可以直接指定 rustup 工具链代理使用特定的工具链，这对于经常测试不同工具链的开发者来说非常方便。如果 cargo、 rustc 或其他工具链中的第一个参数以 + 开头，那么它将被解释为 rustup 工具链的名称，并且会优先使用该工具链。

cargo +beta test

目录覆盖

目录可以被分配给自己的 Rust 工具链，使用 rusup override 。 当一个目录有覆盖时，任何时候都会在该目录内运行 rustc 或 cargo 。 或者它的子目录之一将被调用。

为某个目录使用特定的夜间版本：

rustup override set nightly-2014-12-18

或者某个特定的稳定版本：

rustup override set 1.0.0

要查看正在使用的工具链，请使用 rustup show。若想移除覆盖设置并重新使用默认工具链，请使用 rustup override unset。

每个目录的覆盖都存储在rustup的主目录中一个配置文件。

工具链文件

有些项目被“固定”在Rust的特定版本上，希望这些信息能在它们的源代码仓库中得到反映。这种情况最常见的是那些仅适用于夜间版本的软件，它们会将自己绑定到发布归档中的特定版本。

在这些情况下，工具链可以在项目目录中命名为rust-toolchain.toml或rust-toolchain。 如果两个文件都存在于目录中，则后者用于向后兼容性。 文件使用 [TOML](https://toml.io/格式，并有以下布局：

[toolchain]
channel = "nightly-2020-07-10"
components = [ "rustfmt", "rustc-dev" ]
targets = [ "wasm32-unknown-unknown", "thumbv2-none-eabi" ]
profile = "minimal"

[toolchain]»这一部分是必填项，至少需要指定一个属性。«channel»和«path»是互斥的。

为了向后兼容， rust-toolchain 文件还支持一种旧格式，该格式仅包含工具链名称，且未使用 TOML 编码，例如仅为 nightly-2021-01-21。在这种情况下，文件必须使用 US-ASCII 编码（如果您在 Windows 系统上，请检查编码并确保其不以 BOM 开头）。 rust-toolchain.toml 文件不支持这种旧格式。

如果您在运行 rustc、 cargo 或其他命令时看到以下错误，请按如下方式处理：

error: invalid channel name '[toolchain]' in '/PATH/TO/DIRECTORY/rust-toolchain'

这意味着您正在运行 rustup 版本，且低于 1.23.0 版本，同时试图与一个在 rust-toolchain 版本中使用新 TOML 编码格式的项目进行交互。您需要将rustup 版本升级到 1.23.0 及以上版本。

这些 rust-toolchain.toml/rust-toolchain 文件适合提交到源代码控制。如果已经完成了这一步，那么如果工具链被固定在一个特定的版本上，也应该对 Cargo.lock 进行跟踪，以避免与依赖项出现兼容性问题。

工具链文件设置

频道

“通道”设置指定了要使用的 toolchain。该值是一个字符串，其形式如下：

(<channel>[-<date>])|<custom toolchain name>

<channel>       = stable|beta|nightly|<versioned>[-<prerelease>]
<versioned>     = <major.minor>|<major.minor.patch>
<prerelease>    = beta[.<number>]
<date>          = YYYY-MM-DD

路径

设置 path 允许使用自定义的工具链。该值是一个绝对路径字符串。

由于 path 指令直接指定了一个本地工具链，因此其他选项，比如 components、 targets 和 profile 则没有任何效果。

channel 和 path 是互斥的，因为 path 已经指向了特定的工具链。

个人资料

“配置文件“设置要安装的组件组。值是一个字符串。 有效的选项是：最小化, default, 和 complete。每个选项的详细信息见 profiles。

请注意，如果没有指定，则不一定会使用 default 配置，因为可能已设置了不同的默认配置，即 rustup set profile。

组件

components设置中包含需要安装的额外组件列表。该值是一个字符串列表。有关组件的列表，请参见components部分。请注意，不同的工具链可能提供不同的组件。

这里列出的组件会与当前配置一起被添加。

目标

targets设置包含要为 cross-compilation安装的平台列表。该值是字符串列表。

主机平台会自动被包含进来；这里列出的目标都是可选的。

默认工具链

如果没有其他覆盖设置，将使用全局默认的工具链。这种默认设置可以在安装 rustup 时选择。可以使用 rustup default 命令来设置和查询当前的默认设置。无需任何参数地运行 rustup default 即可打印当前的默认设置。可以通过指定工具链作为参数来更改默认设置。

rustup default nightly-2020-07-27

交叉编译

Rust 支持大量的平台支持情况。对于这些平台中的许多类型，Rust 项目会发布标准库的二进制版本；而对于某些平台，则会发布完整的编译器版本。而rustup工具则能够方便地访问所有这些版本。

当你第一次安装一个工具链时，rustup 只为你的 host 平台安装标准库，也就是说： 您正在运行的架构和操作系统。 要编译到其他平台，您必须安装其他 target 平台。 使用 “rusup targetadd” 命令完成。例如，添加安卓目标：

$ rustup target add arm-linux-androideabi
info: downloading component 'rust-std' for 'arm-linux-androideabi'
info: installing component 'rust-std' for 'arm-linux-androideabi'

使用 arm-linux-androideabi 目标安装后，您就可以通过 --target 标志来构建安卓系统，如在 cargo building --target=arm-Linux-androideabi 中。

请注意，rustup target add仅会为特定目标平台安装 Rust 标准库。通常还需要其他工具来进行交叉编译，比如链接器。例如，要将其编译为 Android 版本，就必须安装Android NDK。未来，rustup将会提供关于如何安装 NDK 组件的帮助。更多详细信息请参考cargo配置文件的目标部分。

如果要为工具链添加目标，且该工具链并非默认工具链，可以使用rustup target add命令中的--toolchain参数来实现，具体步骤如下：

$ rustup target add --toolchain <toolchain> <target>...

要查看可用的目标列表，请执行 rustup target list 命令。如果要删除已添加的目标，可以使用 rustup target remove 命令。

环境变量

  • RUSTUP_LOG（默认：无）。启用 Rustup 的“自定义日志模式”。在这种模式下，可以通过 tracing_subscriber 的指令语法来指定 Rustup 日志行的详细程度。例如，将 RUSTUP_LOG=rustup=DEBUG 设置为接收来自 rustup 本身的日志行，并且最大详细程度为 DEBUG。

  • RUSTUP_HOME（默认值为 ~/.rustup 或 %USERPROFILE%/.rustup）。设置根文件夹为 rustup，用于存储已安装的工具链和配置选项。

  • RUSTUP_TOOLCHAIN（默认值为空）。如果设置此选项，将覆盖所有Rust工具调用所使用的工具链。必须安装具有此名称的工具链，否则工具调用将会失败。该选项可以指定自定义工具链、可安装的工具链，或者工具链的绝对路径。

  • RUSTUP_DIST_SERVER (默认值为 https://static.rust-lang.org)。用于下载与Rust相关的静态资源的根URL。你可以将其更改为使用本地镜像，或者从 staging 目录中测试二进制文件。

  • RUSTUP_DIST_ROOT 已不再推荐使用 (默认: https://static.rust-lang.org/dist)。建议使用 RUSTUP_DIST_SERVER。

  • RUSTUP_UPDATE_ROOT (默认 https://static.rust-lang.org/rustup)。设置用于下载自更新内容的根URL。

  • RUSTUP_VERSION（默认：无）。当执行 rustup-init.sh 或 rustup self update 时，会下载 rustup 的替代版本（例如 1.27.1）。

  • RUSTUP_IO_THREADS 不稳定（默认值为报告的CPU数量，最多为8）。设置用于执行密集I/O操作的线程数量。设置为 1 可以强制使用单线程进行I/O操作以方便故障排查，或者设置任意数值以覆盖自动检测功能。

  • RUSTUP_TRACE_DIR 不稳定（默认：不记录日志）。启用日志记录功能，并指定日志文件存储的目录。日志文件的格式为PID.trace。这些日志文件可以通过Catapult项目的日志记录器进行读取。

  • RUSTUP_TERM_COLOR (默认值为 auto)。用于控制是否在终端中显示彩色输出。设置为 auto 时，仅在 tty 流中使用颜色；设置为 always 时，始终启用颜色显示；设置为 never 时，禁用颜色显示。

  • RUSTUP_UNPACK_RAM 不稳定（默认情况下，会优先使用空闲内存；如果无法判断，则使用500MiB，最低为210MiB）。该值表示在解包过程中将使用的内存大小（以字节为单位），单位为 rustup。

  • RUSTUP_NO_BACKTRACE。即使在设置了 RUST_BACKTRACE 的情况下，也会禁用非恐慌错误时的回溯追踪功能。

  • RUSTUP_PERMIT_COPY_RENAME unstable。如果尝试重命名会导致交叉设备链接错误，则允许Rusup返回复制文件。 这些错误发生在OverlayFS上，它被 Docker使用。 此功能牺牲了一些交易保护，并且可能会在任何时候被删除。Linux。

  • RUSTUP_AUTO_INSTALL (默认：1) 当设置为 1时，当活动工具链不存在时安装。将此值设置为 0 以禁用自动安装。

  • RUSTUP_HARDLINK_PROXIES unstable。设置后，Rusup不会尝试符号链接，而是总是使用硬链接。 如果您发现这个修复问题, 请在rusup issue Tracker上报告这个问题。

  • RUSTUP_TERM_PROGRES_WHEN (默认：auto)。控制是否显示进度条。设置为始终启用进度条，并设置为永远关闭进度条。设置为`永远关闭进度条’。

  • RUSTUP_TERM_WIDTH (默认：无)。允许覆盖进度条的终端宽度。

  • RUSTUP_DOWNLOAD_TIMEOUT unstable (默认：180)。用于覆盖下载组件的默认超时时间(秒)。

  • RUSTUP_CONCURRENT_DOWNLOADS unstable (默认：2) 控制同时下载次数.

  • RUSTUP_TOOLCHAIN_SOURCE unstable。请通过Rusup 告诉代理工具如何确定RUSTUP_TOOLCHAIN。 非生长工具不应设置此环境变量，除非是为了反映早先从生死中的调用。

配置

Rustup 有一个 TOML 设置文件，位于 ${RUSTUP_HOME}/settings.toml 位置（该文件默认设置为 ~/.rustup 或 %USERPROFILE%/.rustup）。该文件的格式并非 rustup 公共接口的一部分——应该通过 rustup CLI 来进行设置查询和更改。

在 Unix 操作系统中，某些设置会参考一个备用配置文件。这个备用文件位于 /etc/rustup/settings.toml 目录下，目前只能定义 default_toolchain 范围内的设置。

网络代理

企业网络通常没有直接对外 HTTP 访问权限，而是强制使用代理服务器。如果你处于这样的网络中，可以通过在环境中设置rustup的 URL 来要求其使用代理服务器。在大多数情况下，设置https_proxy参数应该就足够了。不同系统和 shell 下的命令可能会有所不同。

  • 在支持bash或zsh等 shell 脚本语言的 Unix 类系统中：

    export https_proxy=socks5://proxy.example.com:1080

  • 在 Windows 系统中，命令提示符（cmd）:

    set https_proxy=socks5://proxy.example.com:1080

  • 在 Windows [PowerShell](https://en.wikipedia.org/wiki/PowerShell(或Powershell Core):在 Windows 操作系统上，可以使用 [PowerShell](https://en.wikipedia.org/wiki/PowerShell(或Powershell Core))进行各种操作。

    $env:https_proxy="socks5://proxy.example.com:1080"

  • 当使用 HTTP 代理时，将socks5://proxy.example.com:1080替换为http://proxy.example.com:8080。

如果你需要更复杂的配置，rustup支持与curl程序所使用的约定方式相兼容的操作。这些约定在[curl 的手册页》中的环境部分有详细说明：https://curl.se/docs/manpage.html#:~:text=Environment,%20Environment%20variables。

“curl”这个工具目前已被弃用，不过仍然可以通过设置RUSTUP_USE_CURL环境变量来继续使用它，例如：

RUSTUP_USE_CURL=1 rustup update

请注意，某些版本的libcurl似乎要求在环境变量中去掉http://或https://的前缀。例如，export http_proxy=proxy.example.com:1080（同样也需要设置 HTTPS 相关参数）。如果你通过libcurl使用rustup时遇到“SSL 协议未知”的错误，而通过命令行curl命令则没有问题，那么很可能就是这个问题导致的。

安全性

rustup 对于大多数人来说是足够安全的，但它仍然需要工作。 rustup通过HTTPS进行所有下载，但尚未验证下载签名。

从1.18.4版本开始，安装过程中的文件模式会遵循umask的设置。如果确实需要严格控制权限，建议使用umask。

如果您想报告一个安全问题，请遵循Rust 安全政策。

常见问题解答

这是官方的Rust项目吗？

是的，rustup 是一个官方的 Rust 项目。在 https://www.rust-lang.org 上可以找到关于如何安装 Rust 的官方指导。

这与多锈现象有什么关系呢？

rusup 是 multirust的继承者。 从多精灵开始，是从shell脚本重写多精灵到Rust。 由 Diggory Blake，现在由Rust 项目维护。

可以尝试下载Rust源码吗？

Rust的标准库源可以通过运行 rustup 组件添加 rust-src 来获取。 它将被下载到当前工具链的/lib/rustlib/src/rust` 目录。

编译器和工具的源必须从 Rust 存储库或独立的 source tarballs获取。 

Rustup 在 Windows 系统上运行时出现错误，错误编号为 32。

如果 rustup 在 Windows 系统上出现错误 32，可能是由于后台运行的反病毒扫描导致的。请禁用反病毒扫描程序，然后再次尝试。

出现错误：无法删除‘rustup-bin’文件：‘C:\Users\USER\.cargo\bin\rustup.exe’

如果rustup无法以这种方式进行自我更新，通常是因为正在运行 RLS 程序（即你的编辑器处于打开状态，同时 RLS 也在运行）。解决方法是停止 RLS 的运行（关闭编辑器），然后再尝试一次。

成功终止了 rustup 进程，但是无法执行rustc --version命令。

重新启动你的 shell 进程。这样就能将 Cargo 的 bin 目录（$CARGO_HOME/bin）重新加载到你的PATH环境变量中。
